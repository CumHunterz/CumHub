# CumHub

CumHub 是本地项目与后台任务工作台：保存项目目录、启动项和网页入口，在同一页面访问控制面板、启动服务、查看输出、停止或重启任务。支持一个项目配置多个启动项，关闭浏览器不会停止已启动的任务。

## 启动

需要 [Node.js](https://nodejs.org/) 22.13 或更新版本，使用内置 SQLite，无需安装 npm 依赖或构建前端。

下载源码并解压，然后按系统启动：

| 系统 | 启动方式 |
| --- | --- |
| macOS | 双击 `Start.command` |
| Windows | 双击 `Start.bat` |
| Linux | 运行 `sh Start.sh` |

所有系统也可以在项目目录执行：

```sh
npm start
```

默认打开 `http://127.0.0.1:4310`。macOS 如果提示文件不可执行，可先运行 `chmod +x Start.command`。

运行 `node scripts/launch.mjs --no-open` 只启动本地服务。再次运行启动命令会复用已经运行的服务。使用 `npm run stop` 关闭 CumHub 服务；已经启动的项目任务会继续运行，下次打开 CumHub 会重新连接。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HUB_PORT` | `4310` | 本地服务端口 |
| `HUB_DATA_DIR` | 项目目录下的 `.data` | 项目数据库和运行日志目录 |

例如 macOS/Linux 可使用 `HUB_PORT=4391 npm start`。为兼容已有项目，环境变量、API 和导入文件名沿用 Hub 格式。

## 使用

点击“新建项目”填写目录，然后添加一个或多个启动项。启动项支持：

- 命令，例如 `npm run dev`、`python3 server.py`
- 文件，例如 `.command`、`.sh`、`.py`、`.js`、`.ps1`、`.bat`、`.cmd`
- 可选工作目录、解释器、参数和 JSON 环境变量

在“设置 → 项目布局”中选择竖向布局或横向布局，选择会保存在当前浏览器中。竖向布局使用瀑布流：卡片按自身内容显示高度，后面的项目接到较短的列下面。横向布局每个项目占一行，启动和终端按钮直接可见；点击行首箭头展开全部启动项和网页入口，可以同时展开多个项目。

点击左上角项目图标会打开主控制面板，编辑项目时可以设置该地址；未设置的旧项目会从已有入口中优先选择控制台或管理页。点击目录会复制完整路径并打开文件夹。

每个任务拥有独立的运行记录和输出日志。项目卡片上的“终端”可以直接打开日志，启动项旁也有对应任务的终端入口。正在运行的任务会出现在网页右侧的终端缩略卡片中；点击卡片切换浮窗，拖动标题栏移动，拖动右下角缩放，点击黄色按钮最小化。切换项目页面时浮窗保持可用。关闭或最小化浮窗不会停止任务，停止与重启使用浮窗内的独立按钮。

日志支持暂停、复制和保存输出。点击或选取日志、向上滚动时暂停刷新；每个任务分别保留暂停状态与阅读位置。窄屏下任务栏移到页面底部。数据目录默认为项目下的 `.data/`，可以从页面导出和导入项目备份。

## 数据与边界

项目资料（含启动项配置）保存在 `.data/hub.sqlite`，日志保存在 `.data/runs/`。本地服务只监听 `127.0.0.1`，每次服务启动生成新的 API 令牌，API 不接受跨站请求。删除项目只删除 CumHub 记录，不删除项目目录；删除前需要先停止该项目的运行任务。

CumHub 会在本机执行你配置的命令；它不是远程访问服务或命令沙箱。分享导入文件或备份前应检查其中的绝对路径、环境变量、地址和备注。仓库及发布包不含实际项目数据、日志、密钥、个人导入文件或终端截图，首次启动为空工作台。

## 导入、导出与批量收集

首页的“导入项目”会先显示预览：相同目录的项目会标为“更新”，新目录会标为“新增”，确认后才写入。可以选择多个 JSON、粘贴 JSON，或选择一个包含多个项目的文件夹；文件夹模式只收集名为 `hub-import.json` 的文件，并跳过常见依赖、构建和版本控制目录。

“下载备份”会保存当前项目资料。导入同一个备份不会无止境地产生副本：同项目 ID 或相同目录会进入更新预览。运行任务和日志不会随项目备份导入，也不会因导入自动启动。

新项目完成后可以让 Codex 生成 `hub-import.json`。本仓库的 [HUB-CODEX-PROMPT.md](HUB-CODEX-PROMPT.md) 是可直接复制的短提示词。导入格式和通用示例见 [import-schema.md](skills/hub-project-integration/references/import-schema.md)，示例中的目录和端口需要替换为项目实际值。

## Codex Skill

源码包附带 [hub-project-integration](skills/hub-project-integration/SKILL.md)，发布版本也提供独立的 Skill ZIP。Skill 的入口很短，只有生成配置时才读取导入格式说明；主控制面板优先设置为项目图标的入口，支持批量导入。

将 `hub-project-integration` 文件夹放入 `~/.codex/skills/`（Windows 为 `%USERPROFILE%/.codex/skills/`），然后开启新的 Codex 对话。最终目录应为 `~/.codex/skills/hub-project-integration/SKILL.md`，不要再套一层文件夹。

可以直接使用：

```text
使用 $hub-project-integration。完成项目后生成经过验证的 hub-import.json。
```

Skill 也允许在新建项目、明显修改项目或新增启动入口时自动选择。生成后在 CumHub 中选择“导入项目 → 选择 JSON 文件”，可以同时选多个文件；已有项目可使用“从文件夹收集”批量读取生成过的 `hub-import.json`。

## 开发

```sh
npm test
npm run serve
```

前端是原生 HTML/CSS/JavaScript，服务端使用 Node.js 内置 HTTP、SQLite 和进程 API。测试使用临时目录，不读写个人项目数据库。
